# UX кабинета мастера

Сверка 3 октября 2026 года. Область: вход, общая оболочка, основные разделы кампании, создание и просмотр записей, подготовка/ведение боя. Изменения локальные; production не обновлялся.

## Основные решения

| Проблема | Текущее решение |
|---|---|
| Длинное плоское меню | Три группы: «За столом», «Мир и история», «Справочники». На экранах до 1120 px — раскрываемое меню с названием текущего раздела; пункты доступны в сетке без горизонтальной прокрутки. |
| Шапка конкурирует с содержимым | Поиск и вход в бой остаются на виду; карта, анкеты, AI и общее создание находятся в «Инструментах». Ожидающие проверки AI-результаты и ошибки показываются и снаружи меню. Настройки аккаунта и выход находятся в sidebar. |
| Главная не помогает начать | Три последних сцены с кратким описанием и возможной находкой, до трёх активных квестов и локаций, группа и журнал. Убраны дубли меню и декоративные счётчики; вводный блок появляется только в пустой кампании. |
| Постоянный третий столбец и дубли карточки | Пустой preview не занимает место; открытие полной записи не дублирует её автоматически. Явный быстрый просмотр можно закрыть, на узком экране к нему выполняется прокрутка. |
| Форма требует разобраться во всём сразу | Сначала тип, название, краткое описание; AI, классификация, медиа, тексты игроков, секреты, боевые данные и награды раскрываются отдельно. Сворачивание не удаляет значения. |
| Пустые блоки важнее содержания | В карточке сначала сводка и информация мастера; пустые карточки игроков, заготовленные бои, магазины и связи свёрнуты. |
| Не относящиеся к странице фильтры | Скрыты вкладки главной и вкладки базового модуля над самостоятельными alias-экранами, включая события и заметки. |
| Ложные и технические подписи | Исправлена ссылка «Забыли пароль?», которая открывала регистрацию; «Запомнить логин» точно описывает поведение. Удалены пояснения устройства сетки предметов; подписи новой формы переведены без изменения серверных enum. |
| Лишние подтверждения | Поиск и просмотр галереи закрываются сразу; подтверждения выхода из редакторов сохранены. |
| Перегруженное оформление | `styles/workspace.css` задаёт спокойные поверхности, типографику, акценты и адаптивную оболочку поверх существующих стилей. Убраны лишние градиенты, вложенные рамки и анимация появления панелей; свёрнутые секции занимают меньше места. Семантические цвета боя, изображения и светлый отчёт мастера сохраняются. |

| Тяжёлая выдача справочников | Предметы и каталог бестиария показывают по 48 записей с «Показать ещё»; поиск/фильтрация работают по всей выдаче. Подробные фильтры предметов сворачиваются, число активных условий видно снаружи. Из пустой выдачи доступен сброс. |
| Дубли в заметках и справочниках | Новый черновик не соседствует с сообщением о пустом списке; текст не повторяется над редактором. Источник правила остаётся в подробностях, технический кеш бестиария убран из UI. Статусы квестов показаны по-русски. |

## Проверка и границы

- Успешная production-сборка: TypeScript + Vite. Остаётся предупреждение о крупных JS chunks; ускорение загрузки не измерялось и не заявляется.
- Браузер: вход тестового пользователя, главная, группа/приглашения, локации, события, заметки, сессии, магазины, предметы, правила, бестиарий, подготовка и активный бой; поиск, меню инструментов, настройки аккаунта и открытие карты.
- Проверены размеры 390×844, 1024×768 и 1440×900. Проверены раскрытие/сворачивание мобильной навигации и явный быстрый просмотр.
- Создание локации и редактирование секрета через реальный UI; поле свёрнуто перед сохранением, результат подтверждён в отдельном JSON-хранилище. Рабочие кампании для этой проверки не использовались.
- Отдельный тестовый сервер использует `tmp/ux-review`, включая собственные store и uploads. Снимок главной: `tmp/ux-review/dashboard.jpg` (вне Git).
- Дополнительная проверка общего оформления: основные разделы кампании на широком экране, мобильная навигация и каталоги на 390×844; финальный вид на 1440×900. Подтверждены выдача 48→96 и сброс после поиска в бестиарии, выдача 48→96, пустой поиск/сброс и индикатор свёрнутых фильтров предметов; заметки без противоречащего пустого состояния, раскрытие полной локации, читаемые карточки правил. У предметов и мобильного бестиария подтверждено отсутствие горизонтального переполнения. Снимок: `tmp/ux-review/ux-clean-dashboard.png` (вне Git).
- В этом проходе общего оформления HTTP-контракты, хранение, доступ и правила персонажей не изменены. Конструктор классов остаётся в состоянии, описанном в `CHARACTER_BUILDER_HANDOFF.md`.
- Это проверка основных экранов и изменённых сценариев, а не исчерпывающий тест каждой вложенной формы. Внешний OAuth, AI-генерация, полный импорт удалённых каталогов, показ на физическом ТВ и рабочие публичные ссылки не проверялись.

## Отдельные направления дальнейшего упрощения

Глубокие редакторы карты, боя и персонажей сохраняют предметную сложность. Для следующего прохода полезны наблюдения за реальной подготовкой игры: какие настройки используются регулярно, а какие можно показывать только по запросу. Не удалять правила, данные или рабочие функции по одному лишь наличию большого числа полей.


## Магазины

Выбор магазина перенесён в компактный горизонтальный список; ассортимент и каталог используют ширину рабочей области. Каталог содержит все категории, источник, нормализованные группы редкости, диапазоны цен, тип брони, сортировку и выдачу по 48 с продолжением. Две широкие drop-зоны и явное добавление кнопкой; повторный товар увеличивает количество. Сохранение доступно рядом с каталогом. Пустые кнопки фильтров/меню убраны, поля товара подписаны для screen reader. Несохранённый магазин защищён при выборе другой лавки и закрытии вкладки; переход в другой основной раздел по-прежнему не имеет общего блокировщика навигации.

Описание магазина отделено от GM-заметок о тайниках/проверках. Изображение создаётся через существующий Codex bridge по сохранённым описанию и видимому ассортименту, с необязательным пожеланием к стилю. Скрытые заметки и товары с количеством 0 не попадают в целевой image context. Результат сначала находится в staged proposal; применение меняет только art, отклонение сохраняет прежнюю картинку. После повторного открытия магазина загружается его ожидающий черновик. Независимые изменения сохраняются при трёхстороннем слиянии; конфликт самого поля изображения блокирует применение.

Проверки: web-сборка; полный Go suite; 34 MCP-теста. Новые проверки охватывают JSON persistence, очищенный контекст, запрет обычного patch/create для shop, owner, применение/undo изображения и stale revision. В изолированном store браузером проверены сохранение описания/секретов, фильтры, повторное добавление и drag-and-drop. Вёрстка проверена на 390 и 1440 px; HTTP-проход подтвердил создание/отклонение shop image proposal и сохранение полей. Реальная внешняя генерация изображения не подтверждена: в тестовом аккаунте не завершён вход ChatGPT. Production не обновлялся.
