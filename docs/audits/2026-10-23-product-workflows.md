# Этап 5: законченные сценарии и оставшиеся границы

## Личный AI

Аккаунт → «Мой AI» → Codex или свой сервис. Codex сохраняет прежний device-code вход ChatGPT; объяснение состоит из трёх шагов. Личный API: выбрать сервис → раскрыть «Где взять ключ?» → вставить ключ → проверить → выбрать доступную текстовую модель → использовать. Проверка делает GET models и не запускает генерацию. Доступность конкретной генерации, баланс и ограничения модели проверяются самим провайдером при запросе; список моделей не доказывает успешную генерацию.

Поддержаны OpenAI, Claude (нативный Messages), Gemini, Grok, DeepSeek и публичные HTTPS OpenAI-совместимые API. Обычная ссылка на чат и подписка в чат-приложении не заменяют API-ключ. Произвольные локальные endpoints не разрешены. Для совместимого API требуются `/models` и `/chat/completions`; поставщик должен поддерживать JSON-ответы. Не каждая модель из его каталога подходит для текстовой генерации.

Owner-only GET/POST/DELETE `/api/account/ai`, POST `/api/account/ai/check`: `expectedRevision`, Origin, ограниченный input, безопасные ошибки. Ключи зашифрованы AES-256-GCM с owner/provider/endpoint AAD, мастер-ключ — `SHADOW_EDGE_AI_CREDENTIAL_KEY` (32 случайных байта, base64, секрет окружения). В браузер и ответы ключ не возвращается. Смена Codex сохраняет неактивный личный ключ; «Удалить сохранённый ключ» стирает его. Мастер-ключ нельзя самопроизвольно менять: прежние записи перестанут расшифровываться. Секрет должен сохраняться вместе с операционным планом восстановления; его значение не входит в экспорт кампании.

Текстовые handlers выбирают generator по владельцу, не меняют общий singleton. Codex получает отдельный read-only JSON turn без MCP-записи; последующее применение остаётся прежним подтверждаемым workflow. Личный API обслуживает чат и текстовые черновики; изображения, распознавание сцены и длинный анализ через личный API пока не поддержаны. Выбранный Codex при разрыве подключения не запускает платный API сайта. Общий прежний режим сохранён для существующих аккаунтов; модели и тарифы общего сервера не менялись. В аккаунте можно явно выбрать новый способ. Экран подписки предлагает рабочее подключение AI до запуска платежей.

Capabilities GET account/ai сообщают доступность text/chat/entityDrafts/images/sessionAnalysis и причину. В чате, атласе и сессиях есть статус/действие подключения, недоступный запуск заблокирован. Наличие Codex-подключения не гарантирует доступность инструментов изображений у аккаунта.

Основания адаптеров: [OpenAI/Codex auth](https://developers.openai.com/codex/auth), [Claude API](https://platform.claude.com/docs/en/api/overview), [Gemini compatibility](https://ai.google.dev/gemini-api/docs/openai/), [xAI chat API](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions), [DeepSeek API](https://api-docs.deepseek.com/). Реальные платные запросы этими проверками не выполняются.

## Персонажи и сцены

F05: мастерская показывает покрытие выбранного класса/редакции и отсутствие русских описаний в текущих умениях. Источник ограничений — существующий COVERAGE.md. Это индикация неполноты, а не новая автоматизация механик; 2014/2024 и один класс сохранены.

F06: standalone-лист помечен «На этом устройстве», приглашённый — «В кампании мастера». Прежние JSON backup/import доступны для переноса. Облачная account-библиотека не создана; очистка браузера без копии остаётся риском.

F08: owner GET `/api/campaigns/{id}/capabilities` разделяет atlasEdit/manualScenes/aiScenes/immutableSource. В ready playthrough разрешена своя ручная сцена: выбрать фон → собственная копия изображения → разметить → сохранить → снова открыть/изменить. Исходный атлас защищён, AI шаблона запрещён. SessionMaps не входят в digest источника. API чужой кампании отвечает 404. Права Foundry и публичных клиентов не расширены.

## Экспорт и восстановление входа

F09: owner GET `/api/campaigns/{id}/export` скачивает версионированный JSON snapshot: кампания, транскрипты/сохранённые анализы, серверные листы. Ответ attachment/no-store. Аккаунты, API-ключи, invite/edit/display credentials не экспортируются. Медиа остаются ссылками; файл не является полным архивом файлов, автоматического импорта нет. История ручных правок, архивирование и корзина пока не реализованы.

F12: в настройках заранее создаются 8 случайных recovery-кодов после подтверждения текущего пароля. Сохраняются только SHA-256 digest с привязкой к owner, срок 180 дней; исходные коды показаны один раз с явным скачиванием. POST `/api/auth/recover` проверяет логин/код, задаёт пароль и отзывает все коды, browser/ephemeral sessions и Codex bridge. Сохраняемый AuthVersion защищает от login, проверенного до reset, но выдавшего сессию после reset. GET/POST `/api/account/recovery-codes` owner-only; reset публичный, Origin и IP/account rate limits обязательны. Ошибка кода не раскрывает существование аккаунта. При отсутствии заранее подготовленных кодов нужны привязанный проверенный OAuth или администратор; email-восстановление не заявлено. CLI reset тоже повышает AuthVersion и отзывает коды.

## F07: спецификация единого инвентаря (не реализованная функция)

| Объект | Идентичность и данные | Доступ |
|---|---|---|
| ItemDefinition | `source + edition + sourceId`, либо `campaignId + customId`; имя, описание, правила, базовая цена | Каталог read-only; custom принадлежит мастеру кампании, expectedRevision |
| ShopStock | `campaignId + shopId + stockLineId`; ссылка на definition, количество, цена продажи, revision | Только владелец кампании; snapshot имени/цены при недоступности каталога |
| CharacterInventory | `sheetId + inventoryEntryId`; definitionRef, quantity, containerId, equipped, attuned, charges, revision | Мастер через ownership кампании; игрок через scoped edit-token листа |
| Transfer | `operationId`; from/to, entries, gold delta, expected revisions | Одна серверная транзакция, идемпотентность; повтор не списывает предмет/золото |

Оборудование одного персонажа не меняет definition. Справочник не содержит фактическое золото, количество, настройку и расходуемые заряды. Редакции не сливаются. Автоматические бонусы разрешены лишь для поддержанной механики с валидацией на сервере; неизвестное снаряжение остаётся ручным с понятным статусом.

Миграция: сначала импорт существующих custom IDs без замены; затем dry-run соответствия stock/draft equipment, неоднозначные записи требуют выбора пользователя. Проверки до запуска: два устройства/409, повтор transfer, недостаток золота/остатка, rollback, отзыв player-token, запрет чужой кампании и immutable template. Нужен отдельный выпуск; текущий магазин/редактор персонажа не выдаются за готовую экономику.

Полный `go test ./apps/server/...` прошёл (httpapi 51,208 с). Дополнительный focused run после усиления SSRF-проверок: personal AI/recovery/export/ready scene — прошёл.
