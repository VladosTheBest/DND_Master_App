# Связи: восстановление, конфликт и большие наборы

Свежий проход 24 октября 2026, текущая реализация варианта 3. Только отдельная локальная синтетическая кампания. Production-сессия пользователя не подменялась.

## Исправления по свидетельствам

- **P1, устаревшее восстановление связей.** Перед исправлением restored reason сохранялся с последней campaign revision вместо baseRevision копии; pending copy также не блокировала запись. Сохранение могло затереть параллельное пояснение. [Старая форма](02-relation-stale-before.jpg) показывает копию revision 156 при уже изменённом серверном пояснении. Теперь begin/recover фиксируют собственную revision, а кандидат требует явного выбора.
- **P1, разбор локальной копии.** readRelationDraft проверяет структуру, ID, предел 100 и Unicode reason 2000; повреждённая копия не вызывает сбой формы и остаётся доступна для скачивания. test-relation-drafts.cjs проверяет старую revision, независимость выбора, legacy-compatible shape, повреждения и границы.
- **P2, сохранение при конфликте.** Реальный параллельный PATCH изменил кампанию 156 → 157. Восстановленная локальная копия получила 409, server revision/reason остались прежними. Окно сохраняет текст, сравнивает обе версии, отключает mutation до «Продолжить с моими правками»; эта кнопка сама не отправляет запрос. Затем явное сохранение заменило пояснение. [Сравнение](03-relation-conflict-after.jpg), [прямые API-проверки](relation-conflict-check.json).
- **P2, действия большого выбора.** Header/footer выделены из scroll body. Выбор двух записей из разных фильтров сохранён одним POST, наличие/пояснение проверены с обеих сторон. [Выбор](04-relations-selection-after.jpg). Проверено 116 результатов по пагинации, 100 выбранных; 101-й выбор блокируется, остальные можно снять. [Большой набор](05-large-selection-phone.jpg), [метаданные](large-selection-check.json). 100 связей на сервер не отправлялись.
- **P2, ошибки миниатюры.** Поиск и список используют EntityVisual с contain и sigil при ошибке. На реальной ошибке URL длинного тестового НПС проверен fallback без broken img. [Снимок](08-relation-image-fallback.jpg). Длинное название сохраняется полностью, summary ограничена двумя строками с многоточием.
- Успешная mutation отделена от последующего обновления списка. Ошибка GET после успешной записи больше не предлагает повторить уже сохранённую mutation; есть отдельный retry списка. Это проверено по коду, сетевой отказ GET в браузере отдельно не имитировался. Поля и выбор блокируются на время mutation.
