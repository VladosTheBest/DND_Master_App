# Foundry — ручной обмен, версия 0.13.2

Модуль находится в `packages/foundry-module`. Обмен запускает мастер двумя кнопками: «Обновить с сайта» и «Экспортировать на сайт». При загрузке мира сетевых запросов и таймера синхронизации нет. Полная цель «любой персонаж, все способности, расчёты и анимации без настройки» пока не достигнута: ниже отделены реализованные функции и оставшиеся этапы.

## Установка и подключение

1. Собрать приложение: `npm run build --workspace=@shadow-edge/web`. Prebuild создаёт ZIP в `tmp/foundry/shadow-edge-gm.zip` и копирует его с манифестом в web dist. Docker включает тот же шаг.
2. В установке модулей Foundry указать `https://<сайт>/foundry/module.json`. Сервер подставляет абсолютные manifest/download URL; ZIP выдаётся по `/foundry/shadow-edge-gm.zip`. Для production используется существующий `PUBLIC_BASE_URL`. Публикации в каталоге Foundry пока нет.
3. Установить и включить Shadow Edge GM в мире dnd5e. Анимации уже встроены в пакет; Sequencer, JB2A и отдельная настройка предметов не нужны. Midi-QOL остаётся необязательным дополнением для расширенного расчёта боя.
4. Нажать Shadow Edge GM → «Подключить», указать HTTPS-корень сайта. HTTP поддержан для localhost. На открытой странице войти в кабинет, выбрать свою кампанию и подтвердить подключение. Вернуться в открытое окно Foundry → «Завершить подключение». Модуль завершает разрешение и снова показывает панель с названием кампании; нажать «Обновить с сайта» для загрузки материалов. «Позже» сохраняет незавершённое подключение. Если сайт уже подтвердил разрешение, после перезагрузки достаточно нажать «Обновить с сайта»: модуль завершит подключение сохранённым секретом. Новое подключение для этого не требуется. Кнопка «Новое подключение» создаёт отдельное разрешение вместо текущего.
5. Встроенный боевой workflow уже включён для поддерживаемых действий dnd5e 6. «Дополнительно: Midi-QOL» применяет необязательный профиль Midi-QOL после подтверждения мастером. Предыдущий ConfigSettings сохраняется в настройке мира нашего модуля; есть кнопка восстановления. Эти настройки общие для мира.

Целевой манифест: Foundry **14.368+**, dnd5e **5.3.3–6.0.6**; встроенные эффекты проверены на **14.368 / 6.0.6 / PIXI 7.4.3** с единственным активным модулем Shadow Edge GM. После обновления с 0.4 перезапустить Foundry: манифест 0.5 включает собственный socket-канал. Midi-QOL **14.0.13** для системы 5 или **14.6.x** для системы 6 остаётся необязательной рекомендацией, полный боевой workflow с Midi не проверен. Для системы 6 КД записывается в `attributes.ac.calcs`, для системы 5 сохраняется `calc`; адаптер 5 однократно обновляет старые импорты. Midi-QOL 14.0.x с системой 6 запрещён для применения нашего профиля. Поле `verified` пока не задано.

## Создать сцену с AI

В панели модуля **Создать сцену с AI**: название, описание, целевые размеры в клетках и футы на клетку → создание фона → предпросмотр → создание сцены. Используется подключённый на сайте Codex либо прежний провайдер/модель изображений с подпиской. API-план задаёт тактический вид строго сверху, без надписей, нарисованной сетки, токенов и крыш. Фактическое изображение может отличаться от заданных пропорций: в предпросмотре показаны разрешение и применяемый размер клетки (не менее 50 px).

Генерация — задача существующей серверной AI-очереди, связанная с разрешением этой кампании. **Проверить готовность** проверяет только выбранную задачу по кнопке; фоновой синхронизации нет. Окно можно закрыть и продолжить через ту же кнопку, даже после перезагрузки. Request/job сохраняются в браузере до запроса, повтор не создаёт новый платный вызов в пределах истории задач (50 результатов/7 дней). Ошибка Codex не переключает автоматически на платный API.

После подтверждения фон и настройки сохраняются на сайте как карта сцены (SessionMap), а в Foundry создаётся Scene в папке кампании с загруженным локальным фоном и сеткой. Сцена открывается у мастера, но не активируется для игроков. Повторное подтверждение/«Обновить с сайта» используют её sourceKey/этаж/UUID и не создают дубликат. Автоматического построения стен, освещения и токенов нет. Отклонение фона не создаёт Scene/SessionMap, но может оставить неиспользованное изображение на сайте. Неизменяемые готовые кампании закрыты для генерации.

API: `POST /api/integrations/foundry/v1/scenes/ai`, `GET /api/integrations/foundry/v1/scenes/ai/{jobId}`, `POST .../{jobId}/apply`, прежний scoped asset API. Go покрывает mock image API/сохранение/доступ/повторы, Node — возобновление без таймера, `runtime-scene-ai.cjs` — настоящие окна, FilePicker, decode изображения, grid/folder/Scene и отсутствие дублей на 14.368/6.0.6. Изображение в runtime задано тестом; качество реального AI-фона не проверено.

## AI-настройка НПС и монстров

В листе импортированного НПС/монстра есть кнопка **AI**; в панели Shadow Edge GM — **AI: настроить НПС и монстров** с выбором записей. Запуск ручной, после обычного импорта. Два режима:

- **Настроить существующее** распознаёт исходные атаки, спасброски, названные заклинания и навыки, выбирает встроенные анимации. Не добавляет новые способности, лут или уровень заклинателя; сомнительные действия остаются ручными.
- **Дополнить по описанию** предлагает тематические способности, каталожные заклинания, навыки, уровень полного заклинателя/ячейки и скромный лут. Мастер проверяет дополнения и баланс в предпросмотре.

Редакция 2014/2024 выбирается явно. Каждый актёр проходит отдельный предпросмотр: применить, пропустить, завершить. Есть прогресс и остановка после текущего запроса. Новый запрос использует настроенную модель сайта и активную подписку; неизменённый сохранённый профиль применяется из кэша, новый вариант заказывается отдельным флажком. Ограничение: 60 запросов в час и один одновременно на владельца. Готовые неизменяемые кампании закрыты для AI-настройки.

Профиль хранится отдельно в `foundryAI` сущности сайта, исходный статблок не переписывается. `POST /api/integrations/foundry/v1/actors/ai/preview`, `/apply`, `/undo` используют существующее разрешение кампании; предложение истекает через 30 минут и не принимается после изменения исходника/профиля. После изменения исходника обновление предупреждает об устаревшем AI-профиле; запустите AI повторно. Сложные эффекты, отсутствующие в SRD заклинания и неоднозначные формулы требуют ручной настройки.

В кнопке AI одного актёра доступна отмена последней настройки: снимок хранится в этом браузере мастера. Отмена сохраняет последующие ручные изменения, HP и расход ресурсов. Текущие ячейки при настройке не восстанавливаются. Групповая настройка не запускается автоматически при обновлении и не обрабатывает игроков. Профиль используется при следующем ручном обновлении; повторные дополнения имеют стабильные ключи.

Проверки: Go HTTP-тесты доступа/предпросмотра/сохранения/кэша/отмены/устаревания/валидации; Node-тесты профиля и безопасной отмены; `runtime-actor-ai.cjs` — настоящие окна Foundry 14.368/dnd5e 6.0.6, кнопка в header, оба режима, skip/apply/undo, SRD Shield, лечение и ресурс, ячейки, лут, сохранение ручного навыка/HP. Ответ AI в тестах детерминированный; качество реальной генерации не проверяется этими тестами.

## Реализованный обмен

| На сайте | В Foundry / обратный перенос |
|---|---|
| Игроки и нативные листы конструктора | Character Actor; характеристики, максимальные HP, AC, скорость, класс, владения навыками/спасбросками, ячейки и выбранные заклинания. Экспорт изменений нативного Actor создаёт внешний лист у связанного игрока, сохраняя выборы конструктора. |
| NPC и монстры | NPC Actor, прототип токена и отдельная закрытая GM-заметка. Редактор способности задаёт атаку, спасбросок, лечение или урон, активацию, дальность, тип урона и фиксированный DC. Понятные численные атаки преобразуются автоматически; текстовые/неоднозначные способности остаются ручными. |
| Локации, квесты, лор, события, магазины, подготовка | Закрытые JournalEntry. Изменённые тексты возвращаются в исходную запись. Новым журналам мастер выбирает тип. HTML экспортируется простым текстом. |
| Карты мира | Неактивная Scene с исходным фоном и редактируемыми Drawing-подписями. Перенос текста, позиции, размера, шрифта, цвета и поворота в обе стороны; новые текстовые Drawings возвращаются подписями. Изгиб, ширина дуги, жирность, курсив и обводка сохраняются в metadata, но их оформление в Foundry пока не воспроизводится. |
| Карты сессий | Постоянная библиотека сайта: этажи, фон, размеры, сетка, стены/двери. В Foundry каждый этаж — отдельная Scene с фоном, стенами и сеткой. Существующие данные крыш сохраняются; работу над крышами исключили из текущего плана. |
| Новые Actor, Scene, Journal | Выбор в предпросмотре; новые документы по умолчанию не отмечены. Медиа копируется из хранилища Foundry на сайт, новые ID закрепляются сервером. |

Экспорт исключает текущие HP, потраченные ячейки/ресурсы, эффекты, макросы, combat, туман войны и текущий токен. Состояние открытой двери не считается постоянным изменением. Все Actor получают безопасную публичную биографию; GM-текст хранится отдельно. Удаление источника не удаляет документ Foundry. Подготовленная кампания остаётся неизменяемым шаблоном; экспорт её сюжета, NPC и карт мира блокируется, игроки и отдельные карты сессий разрешены.

Изменения сайта и Foundry сравниваются с сохранённой базой. Независимые поля применяются вместе; конфликт показывает выбор версии. Импорт не меняет Actor во время начавшегося боя. Экспорт требует серверного preview, повторно сверяет hashes при commit, сохраняет весь пакет атомарно и защищает повтор requestId от дублей. Assets загружаются перед окончательным подтверждением пакета: отмена может оставить неиспользуемый файл загрузки. Удаления, автоматическая конверсия отношений в UUID-ссылки и перенос произвольных эффектов/Activities не поддержаны.

## Структура импорта 0.10.1

«Обновить с сайта» перестраивает папки уже импортированных документов, включая неизменённые записи. В актёрах внутри кампании находятся НПС, Монстры и Игроки; это штатные папки Foundry. Журналы разделены на Локации, Квесты, Лор, События, Подготовку, Магазины и другие виды; `parentId` размещает подсущности под родителем. Слишком глубокая цепь объединяется в последнюю папку в пределах native лимита. GM-заметки отделены от изображений. Scenes разделены на карты мира и карты сессий; этажи сгруппированы по карте.

Для изображений создаются отдельные закрытые image Journals в «Галерея · <вид> / <сущность>»: основной арт, уникальные изображения gallery и фоны карт/этажей. Их можно показывать игрокам штатной командой Foundry. Импорт не открывает автоматически GM-тексты. Эти журналы исключены из экспорта текста на сайт. Изображения без разрешённого scoped доступа не скачиваются; ошибку загрузки модуль сообщает, остальные материалы продолжает импортировать. Удалённые на сайте документы и ранее скопированные изображения не удаляются автоматически.

Native лист конструктора получает портрет/галерею связанного player, а Actor и прототип токена — локальный портрет. Файлы находятся в `shadow-edge-gm/<campaignId>/Портреты`, `Галерея`, `Карты`; разные группы имеют отдельный кэш, включая URL-encoded пути. Повтор не скачивает их заново, экспорт узнаёт исходный URL во всех группах. При одинаковых байтах разных изображений предпочтителен исходный URL самого документа; подпись/alt портрета сохраняются.

Оружейные действия становятся native weapon Items с исходным плоским бонусом/уроном и иконкой; обычный дальний выстрел распознаётся как ranged и запускает стрелу, явное метание остаётся thrown. Явный `mechanics.attackMode`/`foundry.attackMode` имеет приоритет. Заклинания сохраняют SRD-иконки либо получают тематическую fallback-иконку. Бонусы и новые дальности не выдумываются.

Лут создаётся при импорте: явная добыча монстра сохраняет количество и условия добывания; верёвка, факел, книга и несколько профессиональных принадлежностей могут добавляться по описанию с пометкой «Предположение». Это ограниченные правила, не AI-генерация полного снаряжения. Цена, магические бонусы и успешное прохождение проверки не назначаются. Предметы можно менять/удалять в Foundry; повторный импорт сохраняет расход/ручные изменения и не восстанавливает удалённый лут. Предположения не записываются в исходные анкеты сайта; отдельного обратного контракта инвентаря/loot пока нет. Во время начатого боя обновление механики Actor по-прежнему откладывается.

Адаптер 10 сравнивает существующие Items с прежним baseline до добавления новых полей. Неизменённый feat преобразуется в weapon созданием нового Item и последующим удалением старого (меняется Item UUID); изменённая вручную способность сохраняется. Native проверка `runtime-presentation.cjs` охватывает миграцию, иерархию, портрет конструктора, картинки/иконки с реальным декодированием, gallery privacy, ranged/bow, повторный кэш, расход/удаление лута, HP, местное описание и экспорт без повторной загрузки портрета. Snapshot/PNG синтетические; `runtime-site-wizard.cjs` отдельно проверяет настоящий обмен с сайтом.

Обновление показывает прогресс по документам, текущую сущность/изображение, обработанное количество и остаток. После завершения окно можно закрыть; при ошибках в нём раскрывается список причин (HTTP сайта, формат файла, запись в Foundry). Ошибки считаются по уникальным адресам изображений, а не названиям NPC. Повторный ручной refresh повторяет неудачные загрузки. Сгенерированные изображения во вложенных папках proposal/media доступны через scoped GET assets внутри owner/campaign. Старый namespace `/uploads/<campaignId>/…` допускается только для точного art/gallery/фона карты своей кампании, без доступа по произвольному имени или упоминанию в тексте. Другие кампании, обход пути и внешние URL запрещены. Модуль импортирует только добавленных в подключённую кампанию монстров, не весь бестиарий.

Распознаются бонусы «+N к попаданию», несколько явно типизированных частей урона, русская фраза спасброска с характеристикой/Сл, половиной урона и радиусом сферы. Явный профиль механики имеет приоритет. Огненные сферы получают fireball-анимацию. N/день становится native ресурсом с расходом при применении; spent не сбрасывается обновлением. `runtime-monster.cjs` проверяет в dnd5e 6.0.6 два native damage rolls разных типов, DC 15, область/half и списание ресурса. Production-проверка: scoped GET реальных legacy/proposal портретов, декодирование изображений в Foundry и native FilePicker upload; health/manifest/ZIP доступны. Внешние картинки по ссылкам остаются неподдержанными, их причины видны в отчёте. Неоднозначные формулы и отсутствующий структурированный список заклинаний автоматически не дополняются.

## Доступ и хранение

Подключение выдаётся владельцем одной кампании, привязано к Origin Foundry и отзывается на `/foundry/connect`. В браузере мастера IndexedDB хранит секрет подключения, исходные записи и базу сравнения; в мире/flags нет bearer-секрета. Смена браузера требует подключения заново. Сервер хранит SHA-256 секрета, owner/campaign/origin и квитанции идемпотентности. Pairing и preview живут в памяти 5 минут. В модуле 0.9.2 `connection.mjs` завершает pairing только по нажатию кнопки; ошибки сохраняют секрет для повторной попытки. При истечении pairing уже подтверждённое разрешение восстанавливается через scoped GET `v1/snapshot`, включая перезапуск сайта; неподтверждённый/отозванный запрос требует нового подключения. Завершение само не импортирует документы. Панель возвращается после подключения/загрузки; API не опрашивается по таймеру. Подтверждение pairing требует cookie; bearer не принимается обычными маршрутами сайта. Разрешён CORS для Origin подключения без credentials. Медиа читается только из namespace своей кампании либо встроенного разрешённого шаблона, без загрузки произвольных внешних URL сервером.

JSON: `foundryConnections`, `foundryReceipts`, `campaign.sessionMaps`, `entity.foundryCharacter`. PostgreSQL migration 7: `foundry_connections` и `foundry_receipts`; maps/external sheets остаются внутри campaign JSONB. Cloud codec включает новые коллекции; обычные редактирования карточек сохраняют внешний лист.

Безопасный профиль механики хранится в `statBlock.actions/bonusActions/reactions/traits[].foundry`, во внешнем листе — `items[].mechanics`. Профиль содержит тип действия, активацию, дальность в футах, ближнюю/дальнюю атаку, способность/DC спасброска, половину/отсутствие урона при успехе и тип урона; формула и бонус используют прежние поля записи. Экспорт читает настоящую коллекцию Activities dnd5e. Поддержана одна простая Activity с одним компонентом урона/лечения и фиксированными числами. ## Автоматизация и оставшиеся этапы

В панели доступен **Каталог анимаций**: выделите исполнителя, отметьте цель и выберите эффект. Предпросмотр локальный, не бросает кубы и не меняет HP. В 56 профилей входят кровавые режущие удары, стихийные клинки, мистические/некротические/ядовитые снаряды, ледяное копьё, метеор, терновый кнут, опутывание, печати и божественная кара. Меч, топор, молот и кинжал используют детальные рисованные текстуры; кровь появляется только при подтверждённом попадании. Лозы Entangle/Spike Growth движутся в постоянной области. Все четыре PNG входят в ZIP, дополнительных пакетов нет. AI получает этот же каталог с описаниями; повторите AI-настройку актёра для выбора новых вариантов. Назначение визуального профиля само по себе не добавляет механики заклинания. Исходники изображений и спецификации генерации: `packages/foundry-module/assets/README.md`.

Встроены собственные процедурные эффекты (`native-effects.mjs`) для Fire Bolt, Ray of Frost, Magic Missile, Cure Wounds, Healing Word, Burning Hands, Fireball, Lightning Bolt, Bless и Shield. Для импортированных атак тип оружия определяется по `baseItem`/identifier/названию RU/EN: лук, арбалет, меч, топор, молот/булава, кинжал, копьё/алебарда, когти/укус; неизвестные ближние атаки получают взмах, дальние — метательный снаряд, урон/save — попадание. Дальняя атака топором/кинжалом/копьём использует метательный эффект. Это оригинальная библиотека рисованных PNG, процедурных текстур и векторных эффектов, внешняя видеотека не включается и не требуется. `sounds.mjs` содержит оригинальные синтезированные звуки для всех 56 профилей: тетива/стрелы, взмах/удар оружия, огонь/гром/лёд/магические тоны. Они запускаются один раз вместе с эффектом на каждом клиенте через Web Audio интерфейсного канала Foundry и используют его регулятор громкости/mute. Никаких звуковых пакетов не нужно. До первого жеста браузер может блокировать аудио: старые звуки не ставятся в очередь. Источники звука отключаются по окончании эффекта/при смене сцены. Для управляемых атак GM запускает эффект после проверки native броска и передаёт признак попадания; для остальных действий `dnd5e.postUseActivity` запускает эффект локально и передаёт ограниченный пакет геометрии через `module.shadow-edge-gm`; при совместимом Midi используется только его RollComplete на клиенте инициатора. ID сообщения/workflow подавляет повторы. Получатели проверяют сцену, профиль, пределы координат/числа целей и права указанного пользователя на Actor; это не серверная аутентификация отправителя socket. Скрытые/невидимые токены не отображаются обычным игрокам. До 40 одновременных эффектов, очистка после завершения/смены сцены. Все 56 профилей идут 2,6 секунды (области — 2,8) с затуханием; звук — 2,6 секунды. Снаряды, удары, лечение и Bless начинаются у исполнителя и переходят к цели; потоки конуса/молнии идут от него к размещённой области. Magic Missile выпускает три светящихся снаряда. `sustained-effects.mjs` на dnd5e 6 связывает жизненный цикл со штатными документами: применение нашего Shield создаёт/обновляет настоящий SRD ActiveEffect с +5 КД без накопления. Постоянный синий пузырь следует токену, исчезает при отключении/удалении/нативном истечении эффекта и восстанавливается при входе на сцену. Это не автоматический выбор реакции и не пересчёт уже разрешённой атаки. Лечение циклически передаёт частицы от исполнителя до окончания native броска, затем ждёт локальный Dice So Nice и затухает за 0,6 секунды; отмена диалога тоже завершает поток. Без Dice So Nice используется окончание обычного броска, минимум 2,6 секунды. ChatMessage-флаг healCast связывает сообщения use/roll; незавершённый видимый поток восстанавливается после обновления клиента. Защита от зависания: поток не более 120 секунд, ожидание сообщения Dice So Nice не более 20 секунд. Щиты обновляются по событиям документов/сцены, без сетевого polling; скрытые токены остаются скрытыми для игроков. При совместимом Midi применение эффектов оставлено ему. Эффекты применяются к Items, импортированным/созданным нашим модулем; произвольные ручные действия без распознанного Activity не анимируются. Наши Items отключают AA во избежание второго эффекта. Ошибка графики не прерывает расчёт. Покрытие механики остаётся partial/manual: визуальный эффект не подтверждает полную автоматизацию правил.

### Кубы Dice So Nice и встроенный бой (0.7)

Атаки оружием и заклинания с attack Activity открывают штатное окно броска у инициатора, включая игрока: обычный/преимущество/помеха, бонусы и native опции. До подтверждения атака не бросается; закрытие окна блокирует кнопку урона. Крит определяется native результатом (с учётом критического порога), а не отдельным режимом попадания. GM проверяет настоящие author/activity/origin/speaker сообщения атаки и рассчитывает попадание без повторного броска; выбранный whisper/blind наследуют карточка и урон. При разрыве соединения во время выбора используйте способность снова. Совместимый Midi управляет собственным процессом отдельно.

Собственная 3D-отрисовка удалена. Dice So Nice устанавливается/включается отдельным параллельным модулем и настраивается его обычным интерфейсом; Shadow Edge рекомендует его, не включает копию внутрь и не меняет цвета/материалы пользователя. Native сообщения попадания, спасбросков и урона автоматически обрабатываются Dice So Nice, ручного второго showForRoll нет. Проверена установленная версия 5.3.4 на 14.368/6.0.6. Без Dice So Nice расчёты и обычные броски чата продолжают работать.

`combat.mjs` работает с dnd5e 6 и нашими Items coverage=partial. При совместимом активном Midi встроенный процесс отключается, чтобы избежать второго расчёта. У атаки должна быть одна отмеченная цель: native Activity.rollAttack учитывает способность, владение, бонусы и сравнивается с текущей КД; натуральная 1 — промах, 20/системный крит — попадание. При попадании владелец атакующего/GM получает кнопку урона. Activity.rollDamage учитывает native бонусы и крит; фиксированные statBlock-профили сохраняют уже посчитанный бонус, не добавляют характеристику второй раз. Демонстрационный «Меч · характеристики» — настоящий SRD weapon с динамическими бонусами.

Fireball использует фактически созданный круг шаблона: включаются токены, чья площадь пересекает радиус, включая союзников/заклинателя внутри него. dnd5e 6/Foundry 14 создаёт Region: используются shapes/testPoint с поддержкой прежних MeasuredTemplate. Placement включается автоматически при использовании AoE, отмена не запускает бой; стоимость отменённого заклинания остаётся по обычному native use. После подтверждения цели фиксируются в карточке, затем удаляется только созданный этой способностью шаблон/Region. Идёт эффект 2,8 секунды: Fireball с огненным снарядом/вспышкой/облаком пламени/искрами, Burning Hands с потоком огня, Lightning Bolt с несколькими светящимися разрядами; конец плавно затухает. Кнопки спасбросков/урона и обработка запросов открываются после окончания эффекта. Пустая область тоже исчезает и проигрывает эффект, затем карточка сообщает отсутствие целей. Другие области не удаляются. При смене сцены эффект очищается; после аварийного прерывания фазы animation новый GM-клиент открывает сохранённую карточку без повтора эффекта. Этот порядок относится к встроенному workflow; при активном совместимом Midi порядок бросков задаёт Midi. Для некруглых legacy MeasuredTemplate нужен native shape на просматриваемой GM сцене. В карточке у владельца каждой цели есть её спасбросок, GM видит все; ролл учитывает native характеристики/владение/бонусы и СЛ заклинателя. Один урон заклинания применяется каждому проверившемуся токену с half/none/full onSave. Урон можно бросить до последнего спасброска: для ожидающих целей он применится после проверки. Native Actor.applyDamage учитывает сопротивления/иммунитеты и временные HP. Linked-токены одного Actor не получают урон дважды.

Решения/HP выполняет выбранный активный GM, игрок отправляет проверяемый запрос через whisper ChatMessage. Очередь, состояние карточки и receipt вместе с обновлением HP защищают от повторных кнопок; технические запросы скрываются/удаляются. Координатор GM-сессии хранится в User-флаге, вкладки одного профиля используют Web Locks. При закрытии последней управляющей сессии того же GM обновить оставшийся клиент. Незавершённый `rolling` после аварийного закрытия не восстанавливается автоматически. Состояние боя/receipts не экспортируется на сайт. Нужен активный мастер; выбор реакции Shield и пересчёт уже разрешённой атаки, концентрация, сложные условные модификаторы, распределение Magic Missile и автоматическое лечение этим процессом не реализованы. Native use продолжает расход ресурсов и обычную подготовку заклинания.

NPC-импорт переносит явные `DEX +5`/`ЛОВ +5` как дополнительный bonus сверх модификатора, простой текст типов dr/di — как native traits. Условные сопротивления остаются текстом для проверки мастером. Адаптер 8 обновляет старые проекции при следующем ручном импорте.

Проверки: 32 unit tests; runtime-combat — настоящий SRD longsword, STR+prof, два GM-клиента, temp HP/повторы, Fireball, спасброски, половина и сопротивление огню; runtime-combat-player — права владельца/отказ чужой цели и один бросок Dice So Nice у GM/player. Runtime Fireball использует реальную Activity и созданный MeasuredTemplate с подменой только интерактивной финализации. runtime-area проходит реальное размещение Region для Fireball/Burning Hands/Lightning Bolt/Thunderwave/Shatter/Ice Storm, проверяет удаление, сохранность посторонней области, отсутствие кнопок/бросков до окончания эффекта и Dice So Nice. runtime-animations проверяет все 34 профиля и очистку Graphics/Sprites. runtime-attack-dialog проверяет окно у атакующего игрока для оружия/Fire Bolt, отсутствие авто-броска, обычный/преимущество/помеху (реальные max/min d20), бонусы, отмену и единственную GM-карточку; runtime-combat отключает интерактивный диалог только тестовым preRollAttack-hook для проверки механики. runtime-sustained проверяет настоящий +5 КД без накопления, истечение Shield на следующем ходу, движение/скрытие/восстановление пузыря, восстановление pending лечения у игрока, окончание потока после локального Dice So Nice и отмену лечения. В пользовательском test мире отдельно проверен Fireball через настоящий предпросмотр/клик Region с Dice So Nice спасбросками и уроном; тестовые HP восстановлены.


### AI-настройка актёров
В обоих режимах есть поле «Описание / указания AI для выбранных актёров» (до 4000 символов). Изменённые указания запускают новый вариант; они сохраняются вместе с профилем. «Настроить существующее» распознаёт заклинания внутри особенностей и их суточные ограничения. Магические особенности можно преобразовать в заклинания без копирования исходной карточки; пассивные особенности остаются особенностями. Цвет встроенной анимации выбирается по описанию/указаниям, например зелёное пламя, без изменения типа урона.

Типизированные формулы с квадратными скобками нормализуются; разные типы урона остаются отдельными бросками. После ошибки формата модель получает одну попытку исправления. Заклинания вне доступного SRD имеют карточку использования с расходом и явным предупреждением о ручном разрешении эффекта в предпросмотре. Полная автоматизация сложных условий и произвольных новых эффектов не гарантируется.
