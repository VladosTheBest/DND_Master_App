# Видеофоны сцен: сайт → Foundry

## Что умеет

В мастерской сцен выберите «Создать сцену» → «Видео по ссылке». Поддерживаются YouTube и прямые HTTPS-ссылки MP4/WebM. На сайте сохраняются URL, начало/длительность фрагмента, предпочтительное разрешение и геометрия стен/дверей/света. Видеофайл и кадр превью не загружаются в хранилище приложения.

YouTube готовится отдельным помощником на машине с Foundry: фрагмент до 10 минут, по умолчанию первые 5 минут, до 1440p с выбором меньшего доступного разрешения. Результат — MP4 H.264/yuv420p, до 30 fps, без звука, faststart; первый кадр JPEG используется для разметки. Перекодирование ограничено двумя потоками. Переход между концом и началом может быть заметен: бесшовность зависит от исходного видео.

Прямой MP4/WebM воспроизводится по исходному URL; качество определяется файлом. Внешний сервер должен разрешать доступ браузерам/Foundry (CORS) и желательно HTTP Range. Границы цикла контролируются модулем, но объём браузерного буфера не гарантируется. Истечение внешней ссылки или её удаление нарушает доступность фона; стены остаются отдельными данными.

## Первое подключение на Windows

1. Обновите модуль Shadow Edge GM до 0.18.0 обычным способом в Foundry.
2. На компьютере, где хранятся данные Foundry, установите актуальные yt-dlp, FFmpeg (включая ffprobe) и поддерживаемый yt-dlp JavaScript runtime — например Node.js 24. Команды должны быть доступны в PATH. Источники: https://github.com/yt-dlp/yt-dlp#installation и https://ffmpeg.org/download.html . Помощник не устанавливает зависимости и не использует cookies браузера автоматически.
3. Скачайте `/foundry/foundry-video-helper.exe` с сайта и запустите в PowerShell:

```powershell
.\foundry-video-helper.exe --foundry-data "$env:LOCALAPPDATA/FoundryVTT/Data" --foundry-url "http://localhost:30000"
```

Укажите фактическую папку **Data**, а не папку программы Foundry. Адрес Foundry должен совпадать с адресом, открытым в браузере, включая подкаталог при наличии. Оставьте помощник работающим во время подготовки. Ключ из его окна вставьте в расширенные настройки формы видео на сайте и в Foundry → Game Settings → Shadow Edge GM → «Ключ локального помощника YouTube». Адрес помощника по умолчанию — `http://127.0.0.1:4197`.

Стабильный ключ хранится в пользовательской конфигурации ОС, вне публичной папки Data. `SHADOW_EDGE_VIDEO_TOKEN` позволяет задать собственный ключ длиной от 24 символов. Ключ хранится в клиентских настройках Foundry, не в мире/кампании; форма сайта не сохраняет его в черновике. Не отправляйте ключ другим игрокам.

4. На сайте вставьте ссылку, задайте название, фрагмент и ширину сетки. Высота следует пропорциям видео. Нажмите «Подготовить фон и разметить стены». Для разметки фон по умолчанию на паузе; кнопка воспроизведения находится снаружи поля.
5. Сохраните сцену. В модуле нажмите «Импортировать видеосцены» либо «Обновить с сайта». Сцена создаётся неактивной. Откройте её через View, проверьте стены/свет и затем активируйте обычным действием Foundry.

Игроки получают обычный фон от Foundry, без YouTube iframe и кнопок видеоплеера. Им не нужен помощник. Файлы лежат в `Data/shadow-edge-gm/video-cache/`; имя зависит от источника, фрагмента, разрешения и версии формата. Повторная подготовка использует кеш, включая после перезапуска помощника. Автоудаления файлов нет; при размере кеша более 8 ГБ новые задания требуют освободить место вручную. Файлы, используемые сценами, удалять нельзя.

## Удалённый Foundry / Linux

Доступен `/foundry/foundry-video-helper-linux-amd64`. На сервере запустите бинарный файл с теми же параметрами и установленными зависимостями. Помощник слушает только loopback. Для обращения с другого компьютера администратор должен настроить HTTPS reverse proxy к помощнику; на сайте и в клиентских настройках модуля указывается этот HTTPS-адрес. Не публикуйте порт помощника напрямую. `--origins` задаёт дополнительные разрешённые Origin, разделённые запятыми; по умолчанию разрешены production-сайт и локальная тестовая версия. Origin самого Foundry берётся из `--foundry-url`.

Браузер может запросить разрешение доступа к локальной сети. При недоступном помощнике подготовка показывает ошибку, разметка/настройки остаются в черновике. Отмена ожидания не убивает подготовку: повторный запрос найдёт готовый результат. Одновременно готовится одно видео, задача ограничена 25 минутами. Извлечение YouTube зависит от текущего yt-dlp и доступности ролика; ошибка не переключает обработку на сервер приложения.

## Разработчику

`apps/server/cmd/foundry-video-helper` — отдельный процесс; `internal/videoprep` валидирует YouTube ID, канонизирует URL, запускает yt-dlp/FFmpeg без shell и поддерживает авторизованные `/health`, `POST /jobs`, `GET /jobs/:id`. CORS ограничен явными Origin; тело до 4 КиБ, bearer key обязателен. CLI `--version` не запускает обработку. Сайт **не** предоставляет эти endpoints: его прежние owner-only session-maps POST/PUT сохраняют optional level.video с revision guard. Произвольные URL не становятся доверенными файлами кампании и не проходят через asset proxy.

`ExternalSceneForm`, `SceneVideoBackground` и optional тип level.video отвечают за браузерное превью/черновики/сохранение. `video-background.mjs` готовит YouTube через локальный помощник, подставляет относительный файл Foundry, настраивает нативный видеоцикл и снимает обработчики при teardown. Видео не отправляется на сайт при экспорте: переносится исходная ссылка и геометрия. Замена подготовленного фона вручную в Foundry требует вернуть исходник перед экспортом. AI-анализ видеопотока не запускается. Docker собирает помощники Windows amd64 и Linux amd64 из тех же исходников и публикует их рядом с модулем.
